## DB-07: Cloudflare injection conflicts with hash-only CSP

Severity: Low

### Evidence

The live HTML was 399,654 bytes. The reviewed inline application scripts match explicit CSP hashes, but Cloudflare added an inline script carrying the changing __CF$cv$params token. Browser consoles can therefore report a refused inline script under the intended hash-only policy.

Cloudflare documents that JavaScript Detections injects a script into HTML and that strict CSP must account for that injection. Cloudflare also documents no-transform as the cache-control directive that prevents response modification:

- https://developers.cloudflare.com/cache/concepts/cache-control/

    +  Cache-Control: public, max-age=0, must-revalidate, no-transform

The hot packet paths are healthy in local Go benchmarks on Apple M5 Max:

| --- | ---: | ---: |

| Dispatch hit fixture | 877.2 ns/op | 108 B, 1 alloc |

| Register 256 tokens | 87.474 us/op | 17,367 B, 163 alloc |
| Register 1024 tokens | 416.587 us/op | 113,431 B, 317 alloc |

| Authenticated init accept | 535 ns/op | 1,176 B, 16 alloc |

The dispatch-hit benchmark includes fixture message creation; it does not prove a table allocation. Registration cost scales sharply with the retained token window. Keep the initial window at 32 and expand only after authenticated demand, which the current design does. Elligator and rejected-init allocations are candidates for profile-guided pooling, but they are session setup paths. Do not add pooling without lifetime, zeroization, and race tests.

Socket buffer code requests up to 8 MiB and reads back the kernel result. Apple H3 caps the client connection receive window at 2 MiB and stream windows at 512 KiB. These are bounded and defensible defaults. MTU, buffer, and QUIC-window changes should wait for real cross-platform bandwidth-delay, loss, battery, and memory measurements.
