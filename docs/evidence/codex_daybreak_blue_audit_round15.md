### DB-H3: Android carrier protection occurs after device activation

**Evidence.** `VpnTunnelService.startAwgEngine` calls `GoBackend.awgTurnOn` at line 3438 and calls `AwgSocketProtection.protectOrRollback` at line 3450. Native `awgTurnOn` applies the complete peer configuration, calls `device.Up()`, and only then returns the handle that exposes socket descriptors. A configured peer can schedule a handshake or persistent keepalive between `device.Up()` and the Java protection calls.

**Root cause.** The JNI contract exposes transport sockets only after a fully configured device is active. Rollback handles protection failure, but it cannot retract a datagram already routed into the new VPN during the timing window.

**Exact fix.** Convert startup into two phases. Phase one applies only interface settings and raises a peerless device. Kotlin protects every exposed socket. Phase two applies the peers. The following targeted contract is complete and must be implemented together:

1. Add `AwgUserspaceConfig.splitProtectedStart`:

```kotlin
internal data class AwgProtectedStart(
    val interfaceSettings: String,
    val peerSettings: String,
)

@Throws(IOException::class)
internal fun splitProtectedStart(settings: String): AwgProtectedStart {
    val interfaceLines = ArrayList<String>()
    val peerLines = ArrayList<String>()
    var inPeers = false
    for (raw in settings.lineSequence()) {
        val line = raw.trim()
        if (line.isEmpty()) continue
        if (line.startsWith("replace_peers=") || line.startsWith("public_key=")) {
            inPeers = true
        }
        if (inPeers) peerLines.add(line) else interfaceLines.add(line)
    }
    if (interfaceLines.none { it.startsWith("private_key=") }) {
        throw IOException("AmneziaWG interface settings have no private key")
    }
    if (peerLines.none { it.startsWith("public_key=") }) {
        throw IOException("AmneziaWG peer settings have no peer")
    }
    val normalizedPeers = ArrayList<String>()
    normalizedPeers.add("replace_peers=true")
    normalizedPeers.addAll(peerLines.filterNot { it.startsWith("replace_peers=") })
    return AwgProtectedStart(
        interfaceSettings = interfaceLines.joinToString("\n", postfix = "\n"),
        peerSettings = normalizedPeers.joinToString("\n", postfix = "\n"),
    )
}
```

### DB-H4: Linux parent timeout does not contain elevated descendants

**Evidence.** `RunArgv` creates an unprivileged process group, waits 15 seconds, sends `SIGTERM`, waits two seconds, then sends `SIGKILL`. Its own comment acknowledges that a group signal can be denied for an elevated leader. Both `RunPrivilegedTunnelCommand` and the v3 posture executor place `sudo` or `pkexec` in that group and run route, firewall, and service commands below it. When the signal is denied, `RunArgv` returns 124 while root work can continue.

**Root cause.** Lifetime enforcement is outside the privilege boundary. Process group membership does not grant an unprivileged process permission to signal a root child after credential transition.

**Exact fix.** Place a trusted root-side GNU `timeout` after the elevator and before `/bin/sh`. Keep the parent watchdog longer than the root budget. Add this helper:

```cpp
std::string TrustedRootTimeout() {
  for (const char* candidate : {"/usr/bin/timeout", "/bin/timeout"}) {
    struct stat metadata = {};
    if (lstat(candidate, &metadata) != 0) continue;
    if (!S_ISREG(metadata.st_mode) || metadata.st_uid != 0) continue;
    if ((metadata.st_mode & (S_IWGRP | S_IWOTH)) != 0) continue;
    return candidate;
  }
  return {};
}

bool AppendRootTimeout(std::vector<std::string>* argv, std::string* error) {
  const std::string timeout = TrustedRootTimeout();
  if (timeout.empty()) {
    if (error != nullptr) {
      *error = "No root-owned, non-writable GNU timeout executable is available";
    }
    return false;
  }
  argv->insert(argv->end(), {
      timeout,
      "--signal=TERM",
      "--kill-after=2s",
      "12s",
  });
  return true;
}
```

In both privileged call sites, start with `std::vector<std::string> argv = elevator;`, call `AppendRootTimeout(&argv, &error)` before inserting `/bin/sh`, and return failure if it refuses. Change the final parent call to `RunArgv(argv, mode, std::chrono::seconds(20))`. Use the same ordering in the v3 posture vector. Do not resolve `timeout` through user-controlled `PATH`.

**Verification.** On Linux, run a test helper that becomes root, forks a TERM-ignoring grandchild, touches a file every 100 ms, and sleeps. Expected: exit 124 from root-side timeout, no surviving process in the helper cgroup or group, and the file stops changing within 14 seconds. Repeat for `sudo -n` and an approved `pkexec` path. ### DB-M1: Windows relay MTU guard is stale

### DB-M3: eager third-party SDK and video cost

**Evidence.** `setupWalletPayments()` runs during page initialization and loads the PayPal SDK. A clean browser therefore made PayPal logger requests before any payment intent. **Exact fix.** Change the video element to:

```html

```

Move `setupWalletPayments()` behind a once-only initializer called by the first pointer, keyboard, or focus interaction with a wallet control. Use this complete gate:

```js
let walletSetupPromise = null;
function ensureWalletPayments() {

    walletSetupPromise = setupWalletPayments().catch((error) => {
      walletSetupPromise = null;

    });

}

```

Remove the unconditional `setupWalletPayments();` call. Apply `data-wallet-action` only to wallet buttons.

### DB-L2: server harness file-handler warnings

**Evidence.** Several otherwise passing server tests emitted `ResourceWarning` for unclosed `master.log` files after repeated in-process imports of the generated hub.

```python
for handler in tuple(hub.logger.handlers):
```
