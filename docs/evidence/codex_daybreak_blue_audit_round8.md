## 5. DB-01: live crypto payment flow can fall into donation mode

**Severity: High**
**State: VERIFIED in live source. Direct physical click postcondition is UNVERIFIED.**

### Evidence

The live homepage returned HTTP 200. Its underlying HTML varied on each request because Cloudflare injected a per-request script, so a whole-file hash is not a stable deployment identity. A sampled response was 399,654 bytes. The workspace `web/index.html` is 399,753 bytes with SHA-256 `e26c1a54371cedb9783f9d0923d3cacc4a1ae222fd77d43c0a8d2c9428752bc3`.

Live source behavior:

* Lines 6483 to 6497 fetch `/api/site/crypto-config`, but return silently on non-200, parse error, fetch error, or both methods disabled.
* Live paid coin buttons are not initially disabled.
* Lines 6730 to 6759 try the generated Monero or BTCPay button. If no generated button was triggered, line 6758 calls `openModal(coin, planTitle)`.
* `openModal` belongs to the static donation feature. It displays a fixed donation address and asks for manual support contact. It does not call `/pay/monero/create-order` or `/pay/crypto/create-invoice`.
* The live main script parses successfully. It contains the paid button click listener. The paid plan button is not statically disabled.
* The configuration endpoint returned HTTP 200 with both methods enabled during this audit. This proves only that the endpoint worked for this probe, not that it worked for the reporting user's browser, cache state, region, or earlier request.

This fully explains the dangerous clash. The two flows share selectors but have different settlement semantics. An automated checkout failure is converted into a donation UI instead of a visible paid-checkout failure. Payment sent through that static path has no automatic order row, expected amount binding, account grant, or delivery outbox entry.

The literal user report, "I can't even seem to click the crypto payments button," was not reproduced with trusted browser input. Edge refused automation while another extension UI was open. No payment button was clicked through that blocked surface. Source inspection narrows the remaining browser-specific causes: stale cached markup, a profile extension overlay, or a visual failure around the nested modal. The live application handler itself exists and parses.

### Root cause

The deployed site is behind the reviewed workspace bytes. The live handler uses a permissive fallback between two semantically different products: paid checkout and donation. Its initialization errors are swallowed. The static modal also remains nested in the page rather than being reparented to `document.body`.

### Exact production fix

Deploy the reviewed current `web/index.html` only after the normal website gate revalidates its exact bytes. The required logic is complete below. It disables paid coin buttons until configuration succeeds, renders an inline error, never calls the static donation modal for a paid selector, and moves the donation backdrop to `document.body`.

```javascript
function setCryptoCoinSelectors(card, moneroEnabled, cryptoEnabled) {
  card.querySelectorAll(".crypto-coin-selector-grid .crypto-coin-btn").forEach((button) => {
    const coin = button.getAttribute("data-switch");
    const enabled = coin === "xmr" ? moneroEnabled :
      (coin === "btc" || coin === "dash") && cryptoEnabled;
    button.disabled = !enabled;
    button.setAttribute("aria-disabled", String(!enabled));
  });
}

function renderCryptoUnavailable(card, message) {
  if (!card) return;
  setCryptoCoinSelectors(card, false, false);
  const row = card.querySelector("[data-crypto-row]");
  if (!row) return;
  row.replaceChildren();
  const notice = document.createElement("p");
  notice.className = "crypto-pay-status";
  notice.setAttribute("role", "status");
  notice.textContent = translateRuntimeText(message);
  row.appendChild(notice);
  const trigger = card.querySelector(".crypto-plan-btn");
  row.hidden = trigger ? trigger.getAttribute("aria-expanded") !== "true" : false;
}

async function setupCryptoPayments() {
  const cards = [...document.querySelectorAll("[data-plan-key]")];
  if (!cards.length) return;
  cards.forEach((card) => setCryptoCoinSelectors(card, false, false));
  const unavailable = "Automated crypto checkout is unavailable. Please retry shortly or choose another payment method.";
  let config = null;
  try {
    const response = await fetch("/api/site/crypto-config", { cache: "no-store" });
    if (!response.ok) throw new Error("Crypto configuration unavailable");
    config = await response.json();
  } catch (_) {
    cards.forEach((card) => renderCryptoUnavailable(card, unavailable));
    return;
  }
  const moneroEnabled = Boolean(config && config.monero_enabled === true);
  const cryptoEnabled = Boolean(config && config.crypto_enabled === true);
  if (!moneroEnabled && !cryptoEnabled) {
    cards.forEach((card) => renderCryptoUnavailable(card, unavailable));
    return;
  }

  for (const card of cards) {
    const planKey = card.dataset.planKey;
    const row = card.querySelector("[data-crypto-row]");
    if (!row || !planKey) continue;
    try {
      buildCryptoRow(row, planKey, moneroEnabled, cryptoEnabled);
      setCryptoCoinSelectors(card, moneroEnabled, cryptoEnabled);
    } catch (_) {
      renderCryptoUnavailable(card, unavailable);
    }
  }
}
```
