## DB-01: live crypto payment controller is blocked and the deployed fallback is wrong

Severity: **High**  
Affected: live website, Cloudflare response transformation, crypto plan checkout  
Evidence: live response plus `web/index.html`, `web/_headers`, `web/_worker.js`

### Verified root causes

At 19:18 EDT, the live CSP allowed the main hash `sha256-/xEynGcgRnJ5g17gUox8eVJMbT6BOetJ909M0cYfk5k=`. The main inline script body delivered in that response was 159,390 bytes and hashed to `sha256-cyQvsH3+eN/QxNZsY2IfmkWN0pfrnKz41K82Gv0cp7U=`. Those values differ. The smaller first-party inline script did match. This is not a theoretical header review: it is a hash over the exact live response bytes.

Cloudflare also injected a 921-byte JavaScript Detections block. Two consecutive GETs produced two different hashes because the injected payload is request-specific. Neither hash was in the CSP. Cloudflare's current documentation states that this injection produces CSP refusal without a nonce and that `Cache-Control: no-transform` prevents the injection. Email obfuscation also rewrote the HTML and injected its decoder. See [Cloudflare JavaScript Detections](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/javascript-detections/), [Email Address Obfuscation](https://developers.cloudflare.com/waf/tools/scrape-shield/email-address-obfuscation/), and [Cache-Control behavior](https://developers.cloudflare.com/cache/concepts/cache-control/).

The live document is older than this workspace. Its `setupCryptoPayments()` returns silently when `/api/site/crypto-config` fails or when both providers are disabled. Coin buttons remain actionable. Their click listener then calls `openModal()`. That modal is a manual donation flow, does not create an invoice, and cannot provision an account. Worse, the backdrop is still nested under hidden `#cryptoDonationDrawer`, so setting `backdrop.hidden = false` can remain visually invisible. This exactly matches a button that appears to do nothing.

The configuration endpoint itself was healthy during the probe: GET returned HTTP 200 with both capabilities enabled. This does not remove the CSP failure or the race before that GET completes.

## DB-06: legacy SPA rule escapes owned firewall custody

Severity: **Medium**  
Affected: optional control-plane direct-origin recovery mode

### Verified root cause

`SPAParamProtocol.datagram_received()` inserts an accept rule at position 1 of built-in `INPUT`. `expire_spa_window()` sleeps inside the hub process and later removes it. A crash or cancellation after insertion loses the expiry task and leaves port 8000 accepted from that address until another external cleanup. The normal installer otherwise owns `WINVPN-HUB-INPUT`, `WINVPN-HUB-FORWARD`, and `WINVPN-HUB-OUTPUT` and never flushes unrelated host rules. This legacy path violates that boundary. Default hidden-origin mode disables it, reducing exposure but not correcting the code.

### Exact remediation

Replace `expire_spa_window` and the direct `subprocess.run` insertion with this complete, crash-resilient transient-timer implementation:

```python
SPA_WINDOW_SECONDS = 20
SPA_WINDOW_TASKS: set[asyncio.Task] = set()
SPA_IPTABLES = "/usr/sbin/iptables"
SPA_SYSTEMD_RUN = "/usr/bin/systemd-run"

def install_spa_window(source_ip: str) -> None:
    address = ipaddress.ip_address(source_ip)
    if address.version != 4:
        raise ValueError("legacy SPA accepts IPv4 sources only")
    normalized_ip = str(address)
    token = hashlib.sha256(
        f"{normalized_ip}:{time.monotonic_ns()}".encode("ascii")
    ).hexdigest()[:20]
    comment = f"winsvpn-spa-{token}"
    rule = [
        "-p", "tcp", "-s", normalized_ip, "--dport", "8000",
        "-m", "comment", "--comment", comment, "-j", "ACCEPT",
    ]
    add_command = [
        SPA_IPTABLES, "--wait", "10", "-I", "WINVPN-HUB-INPUT", "1",
        *rule,
    ]
    delete_command = [
        SPA_IPTABLES, "--wait", "10", "-D", "WINVPN-HUB-INPUT", *rule,
    ]
    subprocess.run(add_command, check=True, timeout=5)
    unit = f"winsvpn-spa-expire-{token}"
    try:
        subprocess.run(
            [
                SPA_SYSTEMD_RUN,
                "--quiet",
                "--collect",
                f"--unit={unit}",
                f"--on-active={SPA_WINDOW_SECONDS}s",
                "--timer-property=AccuracySec=1s",
                "--timer-property=RemainAfterElapse=no",
                "--property=Type=exec",
                *delete_command,
            ],
            check=True,
            timeout=5,
        )
    except Exception:
        subprocess.run(delete_command, check=False, timeout=5)
        raise

async def open_spa_window(source_ip: str) -> None:
    try:
        await asyncio.to_thread(install_spa_window, source_ip)
        logger.info("SPA accepted with a kernel rule and supervised expiry")
    except Exception as exc:
        logger.error("SPA window installation failed: %s", type(exc).__name__)

def schedule_spa_window(source_ip: str) -> None:
    task = asyncio.create_task(open_spa_window(source_ip))
    SPA_WINDOW_TASKS.add(task)
    task.add_done_callback(SPA_WINDOW_TASKS.discard)
```

```python

```

See [systemd-run](https://man7.org/linux/man-pages/man1/systemd-run.1.html).

## Performance and memory assessment

No blanket buffer increase is recommended. The current Go UDP code requests and verifies socket receive buffers, Apple H3 receive windows are bounded, Android removed the full-session Wi-Fi lock, and MTU selection is constrained by protocol plans. Increasing buffers without loss and resident-memory measurements would directly conflict with the iOS memory objective.

Priority order:

1. Fix DB-05, then measure event-loop lag, p50/p95/p99 webhook latency, SQLite busy waits, and thread-pool saturation under replay-safe synthetic load.
2. Enforce and physically measure DB-04. Record `phys_footprint`, available process memory, packet rate, drop counters, and jetsam logs throughout sustained traffic.
3. Benchmark each protocol at fixed loss, RTT, MTU, and CPU governor settings. Compare throughput per CPU-second and joules per GiB, not only peak Mbps.
4. Run FD, HANDLE, RSS, and child-process leak tests for 1,000 connect/disconnect cycles on every native platform.
5. Preserve the existing bounded socket and QUIC windows until those measurements justify a platform-specific change.
