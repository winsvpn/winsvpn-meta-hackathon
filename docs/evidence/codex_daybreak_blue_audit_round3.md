### DB-02: malformed stored protocol state silently downgrades to Winn v1

Severity: **Critical**  
Component: `server/wins_control_plane_setup_ONETOUCH.sh:10884-10911`, `11191-11226`

#### Evidence and root cause

`node_protocol_route_metadata` converts a missing value to `winn/1` and converts every unknown value to `winn/1`. `resolve_served_winn_protocol` returns `winn/1` for anything other than exact `winn/3`. The real embedded hub was invoked with `None`, blank text, `winn/99`, `winn/3x`, integer `3`, and a map. Every case advertised and served `winn/1` with the legacy AWG carrier. Only literal `winn/1` should authorize legacy service.

### WEB-01: executable downloads bypass immutable release custody

Severity: **Critical**  
Component: `web/index.html:4643-4969`, bypass at `6513-6658` and `6741-6749`

#### Evidence and root cause

### LNX-01: saturated engine pipe makes teardown unbounded

Severity: **High**  
Component: `linux/runner/linux_winn3_host.cc:398-419`, `447-490`, `626-657`, `3160-3223`

#### Evidence and root cause

The engine stdin is a blocking pipe. `WriteAll` has no deadline. `FrameWritePump` holds `write_mutex` while writing. `TeardownLocked` first calls `WriteFrameLocked(kClose)`, then later wakes the ring and closes the pipe. bool WriteEngineAll(int fd, const uint8_t* data, size_t size,
```cpp
                    int timeout_ms) {
  const auto deadline = std::chrono::steady_clock::now() +
                        std::chrono::milliseconds(timeout_ms);
  size_t written = 0;
  while (written < size) {
    const ssize_t count = write(fd, data + written, size - written);
    if (count > 0) {
      written += static_cast<size_t>(count);
      continue;
    }
    if (count == 0) return false;
    if (errno == EINTR) continue;
    if (errno != EAGAIN && errno != EWOULDBLOCK) return false;

    const auto now = std::chrono::steady_clock::now();
    if (now >= deadline) return false;
    const auto remaining = std::chrono::duration_cast<std::chrono::milliseconds>(
        deadline - now).count();
    struct pollfd ready = {fd, POLLOUT, 0};
    const int polled = poll(&ready, 1, static_cast<int>(std::max<int64_t>(1, remaining)));
    if (polled < 0 && errno == EINTR) continue;
    if (polled <= 0) return false;
    if ((ready.revents & (POLLERR | POLLHUP | POLLNVAL)) != 0) return false;
  }
  return true;
}
```

### EXT-03: credential expiry causes a persistent proxy outage

Severity: **Medium**  
Component: `lib/browser_bridge_proxy.dart:77-110`, `tools/native_messaging/host/bin/wins_bridge_host.dart:372-388`, `extension/src/core/protocol.js:196-215`, `extension/src/background/controller.js:266-304`, `799-809`

The extension therefore keeps answering with an expired token, never asks for another, and stays broken until the native host reconnects.


Validate the host TTL in `parseCredential` and carry it to the controller. Replace the function with:

```javascript
function parseCredential(raw, id) {
  const port = raw.proxyPort;
  if (!validatePort(port)) {
    return { ok: false, reason: 'credential reply carried no usable port' };
  }
  if (typeof raw.token !== 'string' || raw.token.length < 16 || raw.token.length > 256) {
    return { ok: false, reason: 'credential reply carried no usable token' };
  }
  if (!/^[A-Za-z0-9_-]+$/.test(raw.token)) {
    return { ok: false, reason: 'token is not base64url' };

  return {

      type: 'proxy_credential',
      id,

      expiresInSeconds,

}
```

Static result: no additional confirmed defect.

Positive controls found:

## 8. Performance and memory assessment

### Verified design strengths

* Winn v3 derives inner MTU from path MTU and carrier overhead, checks the engine's reported value, and bounds packet slots to that negotiated size.
* The Linux v3 ring has 2,048 slots and batches up to 32 frames, bounding memory and reducing write calls.
* Linux v1 explicitly sizes socket receive buffers and observes the granted size.
* Data-plane TCP MSS rules are protocol-specific, then fall back to path-MTU clamping.
* Android refuses oversize or invalid tunnel setup rather than silently truncating.
* Apple records both physical footprint and available process memory.

### Required measurements before tuning

1. Measure throughput, CPU cycles per byte, context switches, syscall count, packet drops, p50 and p99 latency, and resident memory at MTUs 1,280, 1,333, 1,380, 1,420, and negotiated v3 floor.
2. Compare ring depths 256, 512, 1,024, and 2,048 with the same packet trace. A 2,048-slot ring at roughly 1,400 bytes consumes about 2.9 MB before vector and frame overhead, which is material on an extension process.
3. Record actual `SO_RCVBUF` and `SO_SNDBUF`, not just requested values. Linux doubles or clamps buffer requests.
4. Profile crypto with platform tools. Do not force an algorithm merely because one CPU has acceleration. Winn v3, AWG, and Xray have different primitives and packet shapes.
5. On Android, compare full-time Wi-Fi low-latency lock against activity-gated lock using device current and packet-loss measurements.
6. On Apple, stress the packet provider with full-size bidirectional packets, reconnect churn, DNS changes, and memory pressure. Record jetsam logs, physical footprint, and remaining budget.

The first performance fix is LNX-01. Throughput is irrelevant if disconnect can hang indefinitely.
