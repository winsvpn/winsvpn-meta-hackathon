# Progress sync to the private repository

`tools/sync_progress.sh` commits and pushes this tree to
`github.com/winsvpn/wins_vpn_private_sync` every 30 minutes. It is scheduled as
a Claude Code scheduled task, `winsvpn-progress-sync`, visible under
**Scheduled** in the sidebar.

    tail -20 .artifacts/sync_progress.log  # what it has been doing
    ./tools/sync_progress.sh               # run one cycle by hand

**Why not launchd or cron.** Both were tried and both are blocked by macOS
privacy protection. A launchd agent got as far as loading and then failed every
run with

    bash: .../tools/sync_progress.sh: Operation not permitted

exit code 126 — TCC refuses a launchd job access to anything under `~/Documents`
unless the interpreter has Full Disk Access, and granting that to `/bin/bash` is
far too broad a permission to hand out for a git sync. `crontab` reported
success but could not be verified, because the sandbox cannot read
`/var/at/tabs`. The Claude Code scheduler already holds the access it needs, so
it is the right home for this.

**One consequence: the task runs only while the app is open.** If it is closed
when a cycle is due, that cycle runs at next launch. Work is never lost — it
simply sits uncommitted until the next run.

A cycle with nothing to commit exits silently and writes no log line, so a quiet
log means a quiet tree, not a broken sync.

## One thing you must do once: authenticate

**Pushes currently fail.** The commits are being made and nothing is being lost,
but they stay on this machine:

    fatal: could not read Username for 'https://github.com'

There is no `gh` CLI installed, and the macOS keychain holds no credential for
`github.com`. This has to be done by you — a credential must never be pasted
into an agent session, and any that has been should be treated as burned and
rotated.

Pick either:

**Personal access token, simplest.** Run a push by hand once in Terminal:

    cd /Users/owner/Documents/wins/source/wins_vpn
    git push origin snapshot/vendored-baseline-20260724

Git will prompt for a username and password. The password is a GitHub personal
access token with `repo` scope, not your account password. The `osxkeychain`
helper is already configured, so it stores the token and every later push,
including the automated ones, works without prompting.

**SSH, better if you use several machines.** Three keys exist in `~/.ssh` but
none is registered with GitHub, and `github.com` is not in `known_hosts`. Add a
key to your GitHub account, then:

    ssh-keyscan github.com >> ~/.ssh/known_hosts
    git remote set-url origin git@github.com:winsvpn/wins_vpn_private_sync.git

Verify either route with `./tools/sync_progress.sh` and check the log says
`pushed to origin/...`.

## What it refuses to commit

The script fails the cycle rather than committing something that should not
leave this machine. It scans file *content*, not names, because a key can be
saved under any filename:

- private key material of any type
- strings shaped like Hugging Face, GitHub, AWS or OpenAI-style tokens
- the registered street address
- AppleDouble sidecars, and the 82 MB `evidence/` tree (also in `.gitignore`)

On a refusal it unstages everything and logs `REFUSED: <reason>`. Fix the file,
then let the next cycle run. **A refusal is the script working, not failing.**

> The address pattern is written with `[[:space:]]` separators rather than as a
> contiguous literal so this scanner does not match its own source. The first
> dry run refused to commit the scanner itself for precisely that reason.

## What it excludes, and why

`.gitignore` now covers two things that would otherwise be swept in by
`git add -A`:

- **`._*` AppleDouble sidecars.** About 6,100 in the working tree. They are
  macOS metadata, never source, and they inflate every file and line count
  taken over this tree. Ignored rather than deleted, as you asked.
- **`winn_protocol_experimental/evidence/`.** 82 MB of json, txt, pcap and
  nftables dumps regenerated by every run. To preserve a specific bundle as an
  artifact, add it by path with `git add -f`.

## Repository damage this uncovered, now repaired

Nothing had been committable since **2026-07-25**. A zero-byte
`.git/index.lock` from a crashed operation that day blocked every index write
for nine days, silently — `git status` still worked, so nothing looked wrong.

AppleDouble contamination had also reached inside `.git` itself: **6,491**
sidecars in `.git/objects`, **105** in `.git/refs` and `.git/logs`, and **3** in
`.git/objects/pack`. Git was reporting `badRefName` errors and failing to read
its own pack index. Every file was verified to carry the AppleDouble magic
`00 05 16 07` before being moved — none was deleted, and all are under
`.artifacts/appledouble_quarantine/`. `git fsck` now reports only dangling
objects, which is normal.

The script re-runs both repairs each cycle, so this cannot silently recur: it
clears an `index.lock` only when no git process is running and the lock is over
ten minutes old, and it quarantines `.git` sidecars only when the magic bytes
match.
